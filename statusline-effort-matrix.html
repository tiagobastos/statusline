Claude Code clamps the effort you pick down to what the active model supports and ships the effective value in effort.level — omitting it entirely when the model has no effort knob. The status line renders that verbatim, so one /effort setting can look different across models, and some show nothing at all.

iHow a cell is derived

The status line owns none of this logic — it draws whatever level arrives in the payload. Claude Code does the clamping upstream:

shown = highest level ≤ picked that the model supports  ·  else absent → no bars
Clamp down
xhigh on Opus 4.6 runs as high — the cell shows ▰▰▰, never a sparkle. It rounds down to the nearest supported level, not up.
Absent = none
Haiku & Sonnet 4.5 have no effort parameter, so Claude Code omits effort and the status line draws no bars — never a phantom medium.

The pill strips the version: every Opus shows opus, every Sonnet sonnet. A version's capability shows up purely in the glyphs, not the label.

★What this build changed

The status line now reads effort.level and trusts it. Previously it parsed a flat effortLevel field that Claude Code doesn't send, so it silently fell back to a configured default — and a stale local table re-clamped xhigh upward to max. Both are gone.

A model with no effort support now renders no effort segment instead of a phantom medium, and there is no version-specific capability table to keep in sync — Claude Code is the single source of truth.
